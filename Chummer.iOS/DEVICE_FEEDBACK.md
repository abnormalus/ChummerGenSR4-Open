# Device feedback — November 17, 2026

## Implemented behavior

- The phone has five pages, including Combat. iPad retains its compact toolbar page menu. Combat brings together initiative, condition monitors, weapons/ammunition, applicable magic/resonance sections and vehicles.
- Card surfaces, headers, foreground text, secondary text and control tint adapt together to light/dark appearance. Weapon/power disclosure labels use semantic primary text, rather than inheriting a low-contrast button tint. Structured rows keep their shading and dividers.
- Base weapon damage expressions resolve imported attribute totals with arithmetic, parentheses and `min`, rounding up as desktop CalculatedDamage does. Original formulas remain editable and unchanged in XML. Enabled category/unarmed improvements are included. Unsupported expressions remain visible. Loaded-ammo damage, installed weapon-mod bonuses, limb-specific strength and optional house rules are not a complete mobile rules implementation.
- Physical initiative passes use enabled saved InitiativePass/InitiativePassAdd improvements with the desktop unique/precedence/custom grouping policy. A manual total override remains available for temporary effects.
- Adept powers show selected attribute and level inline, e.g. `Attribute Boost (AGI) 4`. Powers with no levels do not acquire a redundant trailing rating.
- The first eight condition boxes cannot be blocked. Optional capacity adjustments extend or trim a contiguous tail and cannot erase marked damage. Every third usable box shows its penalty; blocked boxes have no penalty. A shared explanation appears once beside the character tracks. Optional capacity adjustments remain session-only; saved damage counts remain compatible, including imported overflow.
- Spells/spirits require the saved magician flag; adept powers require adept; complex forms/sprites require resonance/technomancer. Mystic adepts have both magician and adept flags. Hidden sections retain their original XML.
- Each vehicle/drone uses its own existing `physicalcmfilled` field and desktop `8 + ceil(Body/2)` capacity. No custom vehicle damage schema or changes to sibling vehicles are introduced.
- Installed display name is `SR 4 Dossier`. The code-owned 1024px RGB dossier icon is reproducibly generated by `python3 scripts/generate-icon.py` from this directory.

## Performance boundary

Previously a SwiftUI task identifier serialized the entire edited character on every body evaluation. Skill bindings also rebuilt the entire skill list, gear and notes repeatedly. Autosave now watches a constant-size edit token; serialization occurs after debounce, on focus loss, or explicit export. XML edits invalidate per-snapshot cached read projections and serialized bytes, while unchanged value snapshots retain their own results. No-op scalar writes preserve the edit token.

On this Mac, 100 repeated edited-character read workloads using a private adept fixture took 41.50s on the prior source and about 0.015s with the cache. This is a model workload comparison, not a physical-device frame-rate measurement. Device responsiveness still needs observation with representative characters.
