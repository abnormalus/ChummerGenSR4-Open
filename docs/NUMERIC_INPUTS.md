# Native numeric input rollout

Use standard Avalonia NumericUpDown for modernized numeric fields. NativeIntegerInput supplies consistent logical sizing, whole-number parsing, step size, formatting and framework range clipping. Existing native catalog markup controls now use this same factory. Decimal fields need an appropriate decimal configuration; never round currency, multipliers or fractional ratings simply to reuse the integer factory.

The shared catalog window supports IRatedCatalogPicker. Item models own rating limits, clamping and calculations; the standard control owns text entry, spin buttons, keyboard behavior and layout. CatalogSelection captures the accepted rating together with the item and purchase options. Notifications publish limits and the model's already-clamped value together. During that publication, the model ignores transient feedback from the control coercing an old value against new limits.

## Completed

Armor-modification selection now uses this native rating editor and the shared catalog picker. Fixed modifications disable rating changes. Search, source links, safe empty/error states, window resizing and cancellation use the same framework as weapon, armor and accessory selection. The former armor-modification form/designer/resources are retired from the shipping desktop application; the historical original source is untouched.

ArmorModPickerModel retains rating-based cost/availability, Armor Cost expressions, FixedValues capacity, the parent's Standard/PerRating/Zero display style, markup and free-purchase options. As before, the availability test uses the marked-up catalog cost even when the display is free; purchase handlers own charging. General modifications plus the parent's allowed categories are eligible, and every category now respects enabled sources. The old query's unparenthesized OR allowed some explicitly matched categories to bypass sources. Selection retains name and category together: the two Transparent Ruthenium Polymer Coating definitions have different prices/sources and must not resolve by name alone. Selection returns canonical identity/rating; non-rated inventory modifications still receive rating zero through the established purchase handlers. Character schema and encoding do not change.

## Remaining rollout

At this stage, the shipping desktop designers contained 145 legacy NumericUpDown declarations across all access modifiers before the quantity migration (the earlier 130 count omitted 15 internal fields); retiring its two fields left 143; the shared number prompt retires one more, leaving 142. This is an inventory baseline, not a count of user-visible defects. The largest groups are preferences (62), creation (24), career (7), nexus selection (6), and improvement creation (4). Gear selection has three; other dialogs include vehicles, quantities, dice, calendars and rule-specific inputs.

Replace these during bounded screen migrations, prioritizing gear/cyberware/vehicle ratings and frequently edited character attributes. Preserve minimum/maximum values, integer versus decimal precision, increments, disabled/read-only states, cost/rule notifications and cancel behavior. Include direct typing, both spin directions, keyboard changes, limits, item switches, empty results, scaling and real purchase/undo checks as relevant. Use the shared factory for new integer controls instead of copying configuration.

The compatibility backend supports native overlays, but globally overlaying every spinner would introduce focus, clipping, scrolling and lifetime integration work across unmigrated screens. Keep that as an explicitly tested bridge option if a specific screen needs it sooner; the preferred path is native control/layout migration. No global replacement is claimed in this stage.

## Gear quantity migration

The career Gear Add/Remove Quantity prompt has two integer fields: quantity (0 through the caller limit) and markup (-99 through 1000). Its compatibility form is replaced with standard native controls through the shared dialog host. Preserve free-purchase behavior, unit-cost rounding, restriction multipliers, capacity checks, expense undo and canonical gear identity. Acceptance must cover explicit confirmation versus title-bar/Escape cancellation, insufficient funds preserving existing improvements, direct typing/spinning/limits, removal to zero, and live theme/scaling. The pre-migration handlers accepted any result except Cancel and removed existing Gear improvements on an unaffordable increase; the latter was reproduced on both platforms and corrected in 0.2.132.

The quantity dialog migration now uses standard native controls and explicit accepted drafts. Its native lifecycle checks cover purchase/removal and cancellation, and platform verification passed in 0.2.132; local startup failed before any window with the previously observed render-timer code -6661. No graphics fallback was introduced. Mac and Windows native baselines both reproduced existing Gear improvements being removed after an unaffordable increase. The rejected-purchase path now preserves those improvements; Mac/Windows validation passed. A native baseline also reproduced recording the old stock count for expense undo (two owned, three bought). New quantity purchases now record the purchased increment. Actual undo/refund and canceled confirmation checks cover the full transition; Mac/Windows validation passed.

## Shared integer prompt migration

`frmSelectNumber` preserves the caller API (bounds, initial draft, description, title, AllowCancel and accepted result) while standard Avalonia controls own input and layout. The default range remains 0..10000000. Required variable-price choices reject ordinary dismissal, but `INativeDialogCancellation` lets the existing Quit workflow unwind them. Forced shutdown returns Cancel, never an accepted zero. All four variable-price creation paths reject that cancellation using the existing empty-GUID creation-failure convention. Rule calculations and serialization stay in their existing callers. Native checks cover user input, configured limits, ordinary cancellation, required-choice shutdown and actual variable-price gear creation; Mac and Windows platform checks passed in 0.2.134.

Caller audit reproduced the same expense-count defect in Create Stack: growing one unit to three recorded one for undo instead of two. Its new expense records now use the additional units, with a headless failing baseline and native stack-confirm/cancel coverage. Older expense records are not rewritten.

Native keyboard checks focus the template TextBox and place its caret at the line boundary before sending Down. In pinned Avalonia 12.1.1, TextBox first consumes arrows that move the caret; unhandled arrows bubble to ButtonSpinner for stepping. This is framework behavior, not a reason to add parallel application key handlers. The synthetic numeric probe records only configured test values when diagnosing this distinction.
